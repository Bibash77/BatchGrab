# Free launch: 10 successful users, then 50–100 active users

0.4.0 replaces the proposed $5 experiment. No monetization objective, payment infrastructure or revenue claim is part of this release. The two promises are selecting useful webpage images and collecting organized web documents.

## First 10 successful users

Finish owner review, deploy the approved static site and submit the store candidate. Until listing approval, offer the honest unpacked beta to willing technical testers; record developer-mode friction separately. Use one owner-approved r/chrome_extensions post and, if suitable, one product-offer comment in the permitted r/smallbusiness promotion thread. Store search becomes the primary distribution route once listed. GitHub README and task guides provide supporting onboarding.

Invite volunteers with an actual task, not indiscriminate install requests. Help them try 3–5 allowed images/documents, check names and contents, and report a redacted failure if needed. Ask permission for later follow-up. Track distinct real task completion with the definitions in MEASUREMENT_PLAN.md. No fixture/agent tests count. Diagnose common failures before expanding distribution.

## First 50 active users

This is a goal, not a predicted conversion rate. Review the first 10 outcomes by images/documents, install friction, unsupported source type and repeat use. Fix demonstrated blockers only. Publish the verified store listing, link guides to installation and add Japanese onboarding already tested in Chrome. Review weekly active use over 28 days, repeat tasks and unresolved failures. Test one narrowly relevant community placement at a time with permission and separate campaign labels. Do not repost automatically or infer customers from traffic.

## First 100 active users

Expand only once real tasks repeatedly succeed and support load is sustainable. Improve the more useful of the two task landing pages based on observed help requests, then repeat the channels that produce successful repeat users. Offer optional help sessions to incoming volunteers; no unsolicited private messaging. Report coverage and cohort sizes. If most volunteers cannot finish a task, pause acquisition expansion and fix the observed workflow rather than adding unrelated features.

## Channel order

1. Chrome Web Store search: direct install intent, but owner account, review and real listing are prerequisites. Use accurate bilingual copy, images and limitations; no keyword stuffing or review incentives.
2. r/chrome_extensions: focused users and self-promotion context, conditional on current rules/account eligibility and owner approval. One disclosed-maker post with real demonstration.
3. Permitted r/smallbusiness quarterly promotion thread: task-relevant consultants/assistants, less focused traffic. Product offer only; no focus-group questionnaire.
4. Existing GitHub documentation: low cost and useful for technical beta users; no assumption that repository views mean activation.
5. Search through useful image/document workflow guides: slower, unproven discovery. Production sitemap/indexability must follow approved deployment, not a fictional origin.

## Feedback decisions

Record why an attempted task failed: unsupported access, missing resources, naming error, duplicate handling, mistaken response content, popup confusion or install friction. Evaluate each real issue for reproduction and frequency. Do not add major capabilities just because a user asks once. Free-first usefulness and repeat use take priority over resource totals and vanity metrics.
